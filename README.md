# Штиль · Отзывы гостей

Гостевой сайт кофейни «Штиль» в Актау. На телефоне гость выбирает бариста и сразу открывает форму оценки. Для экрана кофейни сохранён отдельный QR-сценарий. Данные поступают в существующий Google Apps Script, а [AdminFeedback](https://github.com/Yernaribadulla/AdminFeedback) показывает показатели команды.

## Мобильный интерфейс 2.1

- На главной — один вопрос и имена. В форме — сотрудник, оценка, необязательный комментарий и отправка. Слоганы, повторяющиеся пояснения, шаги и декоративный footer убраны из клиентского UI.
- На смартфоне имя ведёт прямо к форме, включая горизонтальную ориентацию. На широком экране с мышью по умолчанию остаётся QR. Ссылки поддерживают обычную навигацию, открытие в новой вкладке и клавиатуру.
- [QR-режим](https://yernaribadulla.github.io/qrcode2/?kiosk=1) (`?kiosk=1`) принудительно показывает коды на любом устройстве. `?direct=1` открывает форму напрямую на любом экране. Вторичный переключатель находится под списком сотрудников.
- Вместо синусоидальных SVG-полос — фотореалистичная поверхность воды: нерегулярная рябь, естественная пена и блики. Сгенерированный фон WebP весит 174 222 байта, имеет плавный CSS-дрейф и не запускает видео, canvas или JS-цикл. Это художественный фон, не документальная съёмка Каспия. [Ассет и точный prompt](docs/water-asset.md).
- Непрозрачные карточки защищают текст и QR от фактуры воды. Светлая/тёмная тема, плавный переход, fade, пауза и reduced motion сохранены. При сбое фоновой картинки действия доступны на резервном цвете.
- При четырёх сотрудниках главные действия помещаются на первом экране 320×640 и 390×844: выбор имени на главной, оценка и отправка в форме. При большем списке или увеличении текста страница свободно прокручивается.
- QR остаётся на белом поле с отступами, таймером 20 секунд, продлением и прямой ссылкой. Форматы событий, сохранение ввода при ошибке, защита от повторной отправки и внешние платформы сохранены.

[Разбор counc, аргументы и компромиссы](docs/council-ui.md)

Тема и пауза используют ключи `shtil-theme` и `shtil-motion`, как AdminFeedback. На одном origin `yernaribadulla.github.io` выбор синхронизируется между сайтами и вкладками. При недоступном storage интерфейс продолжает работать.

## Запуск

Это статический сайт без сборки и серверных npm-зависимостей. Открывайте через HTTP, а не `file://`: приложение использует ES-модули.

```sh
git clone https://github.com/Yernaribadulla/qrcode2.git
cd qrcode2
npm ci
npm start
```

Сервер слушает только [127.0.0.1:4174](http://127.0.0.1:4174/). Для обычного размещения достаточно файлов репозитория; Node.js нужен только для локальных инструментов и тестов. Можно использовать `python -m http.server 8000`.

Добавьте `?demo=1` для проверки интерфейса. Демо явно отмечено, показывает демонстрационную команду, переносит параметр в QR/ссылку на форму и не выполняет запросов к Sheets, Apps Script или Метрике. Без этого параметра форма при открытии с сотрудником фиксирует настоящий скан.

## Связь с аналитикой

Настройки находятся в [src/config.js](src/config.js). Сохранены исходные spreadsheet ID, `gid=1292898986`, URL Apps Script и счётчик Метрики `110849170` на странице отзыва. Серверный код Apps Script находится вне этого репозитория и не изменялся.

| Событие | Формат запроса в прежний Apps Script |
| --- | --- |
| Открытие формы по QR | JSON `{ "barista": "mukha" }`, без `rating` |
| Отзыв | JSON `{ "barista": "mukha", "rating": 5, "comment": "…" }` |
| Переход на платформу | URL-encoded `type=platform_click&barista=mukha&platform=2gis` |

Поддерживаются `feedback.html?staff=...` и прежний `?barista=...`. QR сохраняет путь `qrcode2/feedback.html` на действующем домене. Идентификатор сотрудника формируется, как раньше: имя в нижнем регистре. Внешние строки вставляются через `textContent`. При отсутствии сотрудника сохраняется прежнее значение `unknown`; в AdminFeedback такие записи не относятся к конкретному сотруднику.

Скан защищён от повторов в одной сессии ключом `scan_logged_<имя>`. Отклонённый сетевой запрос снимает эту отметку. При заблокированном sessionStorage запись скана работает, но межстраничная дедупликация недоступна.

Apps Script по-прежнему вызывается с `mode: no-cors`. Его opaque-ответ **не позволяет подтвердить сохранение строки**. Сетевая ошибка оставляет форму для повтора; экран благодарности появляется после завершения запроса без сетевого исключения. Для подтверждения записи нужен отдельный ответ backend с разрешённым CORS; это не имитируется на клиенте.

## Проверки

```sh
npm ci
npx playwright install --with-deps chromium
npm run format:check
npm test
npm run test:browser
```

11 unit-тестов: парсинг GViz, идентификаторы, старые ссылки, схемы запросов, валидация, демо и ошибки сети. 27 браузерных сценариев: реальное декодирование QR, таймер/продление, фокус, клавиатура и касание, отказ источника, повторная отправка, XSS, shared appearance, обе темы и ширины 320/390/768/1440 px. axe проверяет WCAG A/AA/2.1 AA на выборе сотрудника, QR, форме и благодарности в обеих темах. Отдельно проверены QR на экране 1280×720, первый экран телефона 320×640 / 390×844, один переход к форме, горизонтальный телефон, принудительные QR/direct-режимы и работа при недоступном фото.

Тесты перехватывают записи в Apps Script и запросы Метрики: рабочие отзывы не создаются. Автоматические проверки доступности не заменяют ручную проверку реальных телефонов и сканеров. GitHub Actions запускает тот же набор перед завершением проверки коммита.
